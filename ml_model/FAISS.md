# FAISS indexing and ML integration

Install the ML package from the repository root with `.\.venv\Scripts\python.exe -m pip install -e .`. Configure DATABASE_URL in the root .env or process environment. The index builder only reads public.training_data. It does not change the schema or database rows.

## Build from Neon

Run this from the repository root for a bounded pilot:

```powershell
.\.venv\Scripts\python.exe scripts/index_neon.py artifacts/neon-pilot --limit 1000 --fetch-size 256 --batch-size 16 --workers 4
```

Remove `--limit 1000` to process all eligible rows. Use `--landmark-ids 104169 25719 73107` to restrict the selection. `--device cuda` enables GPU embeddings when the installed PyTorch build supports CUDA. The default is CPU. DATABASE_URL is never passed on the command line.

Database reads use keyset pagination ordered by training_data.id. Only one fetch batch and one embedding batch of images are processed at a time. The ID must be unique and stable, and the source table should remain unchanged during a build. Multiple images with the same landmark_id are retained. DINOv2-small determines its own 384-dimensional embedding size. Normalized inner-product FAISS search preserves the existing cosine-similarity retrieval behavior; the starter file's hardcoded 768 dimensions and L2 scoring are not used.

Successful embedding batches are committed to ordered shards in `<output>.work`. Each checkpoint records the last source row ID, counts, source URLs, and failures. Network errors are retried up to three times when transient. Unreadable, oversized, or unavailable images are recorded and skipped without shifting landmark mappings. Images are downloaded into bounded memory and are not retained on disk. Row provenance lives in sources.json and references use `neon:<row-id>` identifiers. Existing reference-image calibration scripts require local reference photos and cannot directly audit these identifiers; retain or recollect those reference photos before calibrating a new full index.

If interrupted before completion, repeat the same command with `--resume`. Use the same database, model, and landmark selection. Previously committed rows are not downloaded again. An output directory that already exists is never overwritten. Failed rows are recorded as processed; retry them separately after inspecting the failures. Leftover pending directories from an interruption are ignored on resume.

A completed bundle contains:

- landmarks.index and landmark_ids.pkl, as requested in FAISS_Next_Steps.txt
- images.faiss and references.json for the existing LandmarkPipeline loader
- build.json with counts, embedding dimension, and model signature

The two FAISS files contain identical vectors in identical order. Position i corresponds to landmark_ids.pkl[i] and references.json references[i]. Pickle is exported for the requested handoff; the ML loader reads the JSON mapping instead. Only load pickle files generated by this project and obtained from a trusted source.

The flat index keeps every embedding in RAM. One million 384-dimensional float32 vectors alone require approximately 1.54 GB, with additional memory needed for model weights, mappings, and export. Checkpoint shards and both exported index filenames also consume disk space. The million-row build has not been completed or benchmarked by this change.

## Recognize an uploaded image

```python
from landmark_ml import recognize_image

landmark_id, confidence = recognize_image(uploaded_bytes)
```

The function accepts image bytes, a PIL image, a binary file object, or a local image path. LANDMARK_INDEX_PATH and LANDMARK_MODEL_PATH select the bundle directory and local DINOv2 weights. Relative defaults resolve from the repository root. Optional index_path, model_path, device, and top_k arguments are also accepted. A loaded pipeline is cached.

```python
landmark_id, confidence = recognize_image(
    uploaded_bytes,
    index_path="artifacts/neon-pilot",
    model_path="dinov2-small",
)
```

For callers using LandmarkPipeline.predict(), the response retains match_score, confidence_probability, confidence_calibrated, similarity, agreement, and top_matches. The compatibility field confidence equals confidence_probability when compatible calibration is applied, otherwise match_score. recognize_image returns that same confidence value. The raw fallback is a matching score, not a validated probability. Call predict() and inspect confidence_calibrated when the caller needs to distinguish the two.

A newly built index is uncalibrated. Do not copy the old 15-image calibrator into it: calibration is tied to the exact index, labels, model, and top_k. A new calibration and independent evaluation are required. The matcher always selects an indexed landmark; it does not automatically reject unknown landmarks.
